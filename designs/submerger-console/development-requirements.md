# SubMerger 新控制台后续开发需求文档

> 文档状态：可进入技术评审  
> 需求版本：v1.0  
> 原型入口：[submerger-console-prototype.html](./submerger-console-prototype.html)  
> 设计说明：[design-notes.md](./design-notes.md)

## 1. 文档目的

本文档用于指导 SubMerger 控制台从当前单页表单升级到新版轻量控制台，并将硬编码的策略组、规则提供者和路由规则改造成可保存、可校验、可发布的动态配置。

开发完成后必须同时满足以下三个目标：

1. 新界面覆盖当前真实功能，视觉与交互以完整原型为准。
2. 管理员无需修改代码或重新部署 Worker，即可新增和调整策略组、规则提供者及路由规则。
3. 未发布新路由配置时，订阅地址、响应头、通用版与 Stash 版分流、缓存及定时刷新行为与当前版本保持一致。

## 2. 背景与现状

### 2.1 当前实现

| 能力 | 当前实现位置 | 当前数据来源 |
| --- | --- | --- |
| 登录 | `src/index.tsx` | `PASSWORD`、`SALT` 环境变量与认证 Cookie |
| 订阅源管理 | `POST /api/save` | KV 的 `${TABLENAME}` |
| 自建节点 | `GET/POST /api/config`、`src/data/selfNodeData.ts` | KV 的 `${TABLENAME}:config.selfNodeData` |
| 策略组 | `src/utils/generateProxyConfigYaml.ts` | 代码硬编码与 `SUBSCRIBE_PATTERN`、`ONETIME_PATTERN` |
| 规则提供者、路由规则及其它 YAML | `src/data/defaultYmal.ts` | KV 的 `${TABLENAME}:config.defaultYaml` 或代码默认值 |
| 订阅输出 | `/subscribe/:magic`、`/onetime/:magic` | 订阅节点、路由配置和缓存 |

当前 YAML 生成过程为：

1. 读取并合并订阅节点与自建节点。
2. 使用环境变量中的正则表达式筛选节点。
3. 在 `generateProxyConfigYaml.ts` 中生成 `proxies` 与硬编码的 `proxy-groups`。
4. 读取包含基础字段、`rule-providers` 和 `rules` 的 `defaultYaml`。
5. 将两段 YAML 文本直接拼接，分别得到通用版和 Stash 版。

### 2.2 核心问题

- 新增策略组或改变策略组结构必须修改 TypeScript 并重新部署。
- 规则提供者与路由规则只能在大段 YAML 中手工编辑，缺少引用、顺序和语法校验。
- 自建节点与默认 YAML 共用一个保存接口，拆成不同页面后容易产生相互覆盖。
- YAML 通过字符串拼接生成，无法可靠检查顶级字段重复或受管字段冲突。
- 当前管理页混合了大量内联 HTML、CSS 和 JavaScript，后续维护成本较高。

## 3. 产品范围

### 3.1 本期包含

- 登录页。
- 订阅源管理。
- 自建节点管理。
- 路由配置：策略组、路由规则、规则提供者、YAML 模板。
- 订阅输出链接。
- 路由配置的导入、校验、草稿保存、完整输出预览和发布。
- 旧配置迁移、缓存失效和新旧生成结果兼容验证。

### 3.2 本期不包含

- Clash、Mihomo 或 Stash 运行状态控制。
- 延迟测试、规则提供者在线连通性测试和运行日志。
- 总览、系统设置、环境状态、账户中心等没有操作闭环的页面。
- 在控制台修改 `PASSWORD`、`SALT`、`MAGIC`、KV 绑定等部署配置。
- 将不同自建节点协议强制拆成固定字段表单。
- 多用户、角色权限、审批流和完整历史版本管理。

## 4. 总体产品原则

### 4.1 配置所有权

最终 YAML 的字段所有权必须唯一：

| 顶级字段 | 所有者 | 编辑方式 |
| --- | --- | --- |
| `proxies` | 订阅合并器 | 根据订阅源与自建节点动态生成，不允许手工维护 |
| `proxy-groups` | 路由配置 | 策略组可视化编辑器生成 |
| `rule-providers` | 路由配置 | 规则提供者可视化编辑器生成 |
| `rules` | 路由配置 | 路由规则可视化编辑器生成 |
| 其它顶级字段 | YAML 模板 | 原始 YAML 统一编辑，包括 DNS、端口、TUN、sniffer、profile 等 |

YAML 模板中出现四个受管字段时，必须阻止发布，不允许以覆盖顺序解决冲突。

### 4.2 轻量实现原则

- 原型是视觉与交互参考，不是生产运行时依赖。
- 生产界面继续基于 Hono 与少量浏览器端 TypeScript/JavaScript 实现，不引入 CDN React、浏览器 Babel 或完整 SPA 框架。
- 将当前 `src/index.tsx` 中的页面、样式和浏览器端逻辑拆分到独立模块，Wrangler 构建后仍部署为单个 Worker。
- 页面中的每个按钮都必须对应真实操作；未实现能力不保留入口。

## 5. UI 改造需求

### 5.1 全局框架

#### 页面结构

- 未登录访问 `/` 时显示独立登录页。
- 登录后访问 `/dashboard`，使用左侧导航与右侧工作区。
- 侧栏仅保留以下四个入口：
  1. 订阅源
  2. 自建节点
  3. 路由配置
  4. 订阅输出
- 页面状态使用 URL Hash 保存：`#subscriptions`、`#nodes`、`#routing`、`#links`。
- 刷新、浏览器前进后退或直接访问 Hash 后，必须回到对应页面。

#### 页面标题栏

- 显示当前页面名称、保存状态和该页面的主要操作。
- 不显示面包屑、架构版本、运行区域、虚构指标或产品介绍文案。
- 状态仅允许显示真实数据，例如“3 个订阅源”“有未保存更改”“修订 18 已发布”。

#### 通用交互

- 请求进行中时禁用重复提交并显示加载状态。
- 保存成功与失败使用简短 Toast；字段错误必须贴近字段展示。
- 有未保存修改时切换页面或关闭页面，需要二次确认。
- 删除订阅源、策略组和规则提供者时需要确认；存在引用时必须阻止删除并列出引用位置。
- 键盘焦点、按钮可访问名称、表单标签和对比度需要满足基本可访问性要求。
- 桌面宽度下保持原型的多栏布局；窄于 900px 时侧栏变为可收起导航，多栏编辑器改为纵向排列。

#### 明确移除的元素

- 总览、系统设置、生产环境卡片和管理员账户入口。
- “配置架构”“生成流程”“这里不是表单目录”等解释卡片。
- 没有后端实现的刷新、连接测试、运行状态和延迟指标。
- 仅用于填充空白区域的说明、徽章和统计数字。

空状态、字段格式提示、校验错误、引用数量和节点匹配数量属于实际操作反馈，可以保留。

### 5.2 登录页

#### UI 要求

- 品牌标识、密码输入框、显示/隐藏密码按钮、登录按钮。
- 不增加用户名、记住我、找回密码或注册入口。
- 错误信息显示在密码字段下方。

#### 交互要求

- 点击登录或在密码框按 Enter，调用现有 `POST /login`。
- 成功后跳转 `/dashboard#subscriptions`。
- 密码错误保持输入焦点并显示“密码不正确”。
- 会话过期后，页面请求收到 401 时统一跳回登录页。

#### 验收标准

- 正确密码可以进入控制台，错误密码不能进入。
- 页面不在浏览器日志或 Worker 日志中输出明文密码。
- 认证 Cookie 的 `httpOnly`、`secure`、`sameSite` 与当前安全属性保持不降低。

### 5.3 订阅源页

#### UI 要求

- 使用可直接编辑的表格，列为：名称、订阅类型、订阅 URL、操作。
- 页面主操作为“新增订阅源”和“保存”。
- 订阅类型仅允许“包年/包月”和“流量包”。
- 删除按钮位于对应行，不增加流量统计、机场在线状态等无数据来源的字段。

#### 校验规则

- 名称：必填，保存前去除首尾空格。
- 类型：必须属于 `SubscriptionType` 枚举。
- URL：必填，首期仅接受合法的 `http://` 或 `https://` 地址。
- 首期保持现有接口约束：至少保留一条订阅源；如需允许清空，应单独变更接口约定。
- 不因名称或 URL 重复自动合并数据，避免改变现有语义。

#### 保存行为

- 保存成功后更新页面基线并清除“未保存”状态。
- 保存失败时保留用户输入。
- 订阅源发生变化后清理包年包月和流量包的两个 YAML 缓存键。

### 5.4 自建节点页

#### UI 要求

- 左侧显示从 JSON 实时解析出的节点列表，至少展示节点名称、协议和服务器地址。
- 右侧保留完整 JSON 编辑器、行号、格式化、校验状态和“保存节点”按钮。
- 不把 SS、VMess、Trojan 等协议拆成不完整的固定表单。

#### 校验规则

- 空数组 `[]` 合法，表示不使用自建节点。
- 根节点必须是数组，每个元素必须是对象。
- 每个节点必须具有非空 `name`；名称在自建节点数组内必须唯一。
- 保存时保留节点对象中的未知字段，不对协议字段做破坏性清洗。
- 无效 JSON、缺失名称或重复名称时禁止保存。

#### 生成兼容要求

- 读取后继续为节点名称追加 `【自建】`，原始 KV 数据中不写入该后缀。
- 同一次生成中后缀只能追加一次。
- 保存自建节点后清理两类订阅输出缓存。

### 5.5 路由配置页

#### 顶部操作

- “导入”：从完整 Clash YAML 解析为草稿。
- “校验”：执行与发布相同的服务端校验，不写入已发布配置。
- “保存草稿”：保存当前编辑状态，但不影响订阅输出，不清理缓存。
- “发布”：校验成功后设为当前生效配置，递增修订号并清理两个输出缓存。
- 页面需要显示“已保存”“有未保存更改”“草稿已保存”“修订 N 已发布”等真实状态。

#### 5.5.1 策略组

##### 列表区

- 展示策略组名称、类型、启用状态和当前节点匹配数量。
- 支持名称或类型搜索、新建、选择、复制和删除。
- 策略组顺序即最终 `proxy-groups` 输出顺序，应支持调整顺序。

##### 编辑字段

- 名称：必填且全局唯一。
- 类型：`select`、`url-test`、`fallback`、`load-balance`。
- 启用状态：停用后不写入最终 YAML，也不能被启用的规则或策略组引用。
- 成员来源可以包含多个，并按界面顺序合并：
  - 节点筛选器
  - 引用其它策略组
  - 内置策略

##### 节点筛选器

- 节点范围：全部节点、仅订阅节点、仅自建节点。
- 包含正则：空值等价于全部匹配。
- 排除正则：在包含正则之后执行。
- 适用输出：全部、仅包年包月、仅流量包。
- 当现有 `SUBSCRIBE_PATTERN` 与 `ONETIME_PATTERN` 的同一筛选项不一致时，迁移为两个不同适用范围的来源，避免改变原有两类订阅效果。

##### 引用与内置策略

- 引用其它策略组时保存稳定 `groupId`，生成 YAML 时转换成最新组名。
- 禁止引用自身或形成循环依赖。
- 首期内置策略至少支持 `DIRECT`；其它内置值只有在通用版和 Stash 版均通过兼容测试后才能开放。

##### 类型相关字段

| 类型 | 必填字段 |
| --- | --- |
| `select` | 成员来源 |
| `url-test` | 成员来源、测试地址、间隔、延迟容差 |
| `fallback` | 成员来源、测试地址、间隔 |
| `load-balance` | 成员来源、测试地址、间隔、负载策略 |

- 测试地址必须是合法 HTTP/HTTPS URL。
- 间隔必须为正整数。
- `load-balance` 的负载策略必须显式选择，不能生成不完整配置。

##### 节点匹配预览

- 展示当前订阅类型和客户端条件下实际解析出的前若干个节点及总数量。
- 无匹配节点时显示警告，但允许保存草稿；发布是否阻断由校验规则决定。
- 预览数据必须来自真实解析结果，不使用原型中的模拟节点名称。

#### 5.5.2 路由规则

##### UI 与字段

- 支持分类筛选、关键字搜索、新增、启停、编辑、删除和顺序调整。
- 规则字段包括：匹配类型、匹配内容、目标策略组、`no-resolve` 和界面分类。
- 界面分类仅用于管理与筛选，不写入 YAML。
- 目标策略组保存稳定 `groupId`，策略组改名后规则自动使用新名称。
- `RULE-SET` 规则保存稳定 `providerId`，规则提供者改名后引用不失效。

##### 首期支持的匹配类型

- `DOMAIN`
- `DOMAIN-SUFFIX`
- `DOMAIN-KEYWORD`
- `IP-CIDR`
- `RULE-SET`
- `PROCESS-NAME`
- `GEOIP`
- `MATCH`

未支持的规则类型在导入时必须明确报错，不允许静默丢弃。

##### 顺序规则

- 启用规则的界面顺序必须与最终 YAML 完全一致。
- 新规则默认插入最终 `MATCH` 之前。
- `MATCH` 不需要匹配内容，且必须是最后一条启用规则。
- `no-resolve` 对不支持该选项的类型应自动禁用或在校验时拒绝。

#### 5.5.3 规则提供者

##### UI 与字段

- 支持搜索、新建、启停、编辑和删除。
- 字段包括：名称、行为模式、下载地址、更新间隔和生成路径。
- 行为模式支持 `classical`、`domain`、`ipcidr`。
- 类型首期固定为 `http`。
- 生成路径默认使用 `./RuleSet/{name}.yaml`，保存的数据中仍应保留明确的 `path`，避免导入后信息丢失。
- 列表中的引用数量必须由当前规则实时计算。

##### 校验规则

- 名称必填且全局唯一。
- 下载地址必须是合法 HTTP/HTTPS URL。
- 更新间隔必须为正整数。
- 被启用规则引用时禁止停用或删除，除非先处理对应规则。
- 本期不提供远端下载或连接测试按钮。

#### 5.5.4 YAML 模板

##### UI 要求

- 左侧显示从原始文本解析出的顶级字段大纲，点击后定位到对应行。
- 右侧为同一个原始 YAML 编辑器，不将 DNS 单独拆成表单。
- 提供“恢复默认”“整理格式”和“完整输出”三个实际操作。
- 显示行数、语法错误、重复顶级字段和受管字段冲突。

##### 内容边界

- 可以维护 DNS、端口、模式、日志、TUN、sniffer、profile 及未来新增的其它顶级字段。
- 不允许出现 `proxies`、`proxy-groups`、`rule-providers`、`rules`。
- 根节点必须是 YAML Mapping；空文本可以按空 Mapping 处理。
- 格式化前需要二次确认，因为格式化可能改变注释位置与引号风格。

#### 5.5.5 导入与完整输出

##### YAML 导入

- 输入完整 Clash YAML 后，解析并拆分四类数据：
  - `proxy-groups` 转为策略组。
  - `rule-providers` 转为规则提供者。
  - `rules` 转为结构化规则。
  - 其它顶级字段保留为 YAML 模板。
- `proxies` 属于运行时节点，不导入草稿。
- 导入仅替换当前草稿，不直接发布。
- 对不支持的组类型、规则类型或字段给出具体错误；不得静默删除。
- 导入成功后显示变更数量，并要求用户再次校验和发布。

##### 完整输出

- 可以切换“通用”和“Stash”。
- 可以切换“包年/包月”和“流量包”，避免只验证其中一个节点集合。
- 预览使用当前草稿和真实节点解析结果，但不写 KV、不修改发布修订、不污染正式缓存。
- 支持复制完整 YAML。

### 5.6 订阅输出页

#### UI 要求

- 展示两行真实输出：包年/包月、流量包。
- 每行显示完整 URL、当前对应订阅源数量和复制按钮。
- URL 分别使用 `/subscribe/:magic` 与 `/onetime/:magic`。
- 不增加在线测试、最近刷新时间、运行日志或下载统计。

#### 验收标准

- 链接与当前部署域名、`MAGIC` 完整拼接。
- 复制成功后给出短暂反馈。
- 订阅源数量根据当前已保存数据实时计算。

## 6. 功能与技术改造需求

### 6.1 推荐模块拆分

| 模块 | 职责 |
| --- | --- |
| `src/index.tsx` | Worker 入口、中间件与路由注册，不再承载大段页面字符串 |
| `src/ui/` | 登录页、控制台 Shell、四个业务页、样式与浏览器端交互 |
| `src/config/routingConfig.ts` | 路由配置类型、默认值、KV 读写和修订控制 |
| `src/config/routingMigration.ts` | 旧 `defaultYaml`、硬编码策略组和环境变量的迁移 |
| `src/utils/validateRoutingConfig.ts` | 发布前服务端校验 |
| `src/utils/generateProxyConfigYaml.ts` | 读取已发布配置并生成两类客户端 YAML |
| `src/utils/resolveProxyGroups.ts` | 节点筛选、引用解析、去重与循环检查 |
| `src/types/types.d.ts` | 订阅、节点、路由配置和 API 类型 |
| `test/` | 单元测试、黄金样本、KV 集成测试和接口测试 |

具体文件名可以在技术评审时调整，但需要保持 UI、存储、校验和 YAML 生成职责分离。

### 6.2 路由配置数据模型

建议使用以下等价模型，字段可以按项目规范微调：

```ts
type OutputScope = "all" | "monthly" | "trafficPackage";
type ProxyGroupType = "select" | "url-test" | "fallback" | "load-balance";

interface RoutingConfig {
  /** 配置结构版本，用于后续迁移。 */
  schemaVersion: 1;
  /** 非受管顶级字段的原始 YAML。 */
  baseYaml: string;
  /** 按输出顺序保存的策略组。 */
  groups: ProxyGroupConfig[];
  /** 规则提供者列表。 */
  providers: RuleProviderConfig[];
  /** 按匹配顺序保存的路由规则。 */
  rules: RoutingRuleConfig[];
}

interface ProxyGroupConfig {
  /** 不随改名变化的内部 ID。 */
  id: string;
  name: string;
  type: ProxyGroupType;
  enabled: boolean;
  sources: ProxyMemberSource[];
  healthCheck?: {
    url: string;
    interval: number;
    tolerance?: number;
    strategy?: string;
  };
}

type ProxyMemberSource =
  | {
      id: string;
      kind: "filter";
      source: "all" | "subscription" | "self";
      include: string;
      exclude: string;
      appliesTo: OutputScope;
    }
  | {
      id: string;
      kind: "group";
      groupId: string;
      appliesTo: OutputScope;
    }
  | {
      id: string;
      kind: "builtin";
      value: "DIRECT";
      appliesTo: OutputScope;
    };

interface RuleProviderConfig {
  id: string;
  name: string;
  enabled: boolean;
  type: "http";
  behavior: "classical" | "domain" | "ipcidr";
  url: string;
  path: string;
  interval: number;
}

interface RoutingRuleConfig {
  id: string;
  enabled: boolean;
  category: string;
  type: string;
  value?: string;
  providerId?: string;
  targetGroupId: string;
  noResolve: boolean;
}

interface RoutingConfigSnapshot {
  revision: number;
  updatedAt: string;
  config: RoutingConfig;
}
```

关键要求：

- 引用关系使用稳定 ID，YAML 输出时才转换为名称。
- 数组顺序就是最终输出顺序，不依赖对象键顺序或前端临时排序。
- UI 专用字段如 `category` 不写入 YAML。
- 存储层必须校验 `schemaVersion`，未知版本不能直接发布。

### 6.3 KV 存储规划

建议新增独立键，避免不同页面相互覆盖：

| KV 键 | 内容 |
| --- | --- |
| `${TABLENAME}` | 保持现有订阅源数组 |
| `${TABLENAME}:self-nodes` | 自建节点原始 JSON 与更新时间 |
| `${TABLENAME}:routing:draft` | 最近保存的路由草稿 |
| `${TABLENAME}:routing:published` | 当前已发布路由配置与修订号 |
| `${TABLENAME}:config` | 旧版兼容读取，保留 `selfNodeData`、`defaultYaml` |

读取优先级：

1. 新键存在时读取新键。
2. 新键不存在时读取 `${TABLENAME}:config`。
3. KV 均无数据时回退到代码默认值。

草稿和已发布配置必须分开。保存草稿不得影响订阅输出；只有发布成功后才更新生效配置和清理缓存。

### 6.4 API 调整

所有新 API 继续受认证中间件保护。HTML 页面未登录时可以重定向，`/api/*` 未登录时应返回 JSON 401，便于前端统一处理会话过期。

#### 订阅源

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| `GET` | `/api/subscriptions` | 获取订阅源 |
| `PUT` | `/api/subscriptions` | 校验并保存全部订阅源，成功后清缓存 |
| `POST` | `/api/save` | 兼容旧页面，内部复用同一保存服务 |

#### 自建节点

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| `GET` | `/api/self-nodes` | 获取原始 JSON 与解析摘要 |
| `PUT` | `/api/self-nodes` | 校验并保存节点，成功后清缓存 |
| `GET/POST` | `/api/config` | 过渡期兼容旧页面，不再作为新 UI 的保存入口 |

#### 路由配置

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| `GET` | `/api/routing-config` | 获取草稿、已发布修订与迁移状态 |
| `PUT` | `/api/routing-config/draft` | 保存草稿，不清缓存 |
| `POST` | `/api/routing-config/validate` | 执行服务端校验 |
| `POST` | `/api/routing-config/preview` | 生成草稿的通用或 Stash 完整预览 |
| `POST` | `/api/routing-config/publish` | 校验并发布，递增修订号并清缓存 |

#### 订阅输出信息

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| `GET` | `/api/outputs` | 返回两类完整 URL 及各自订阅源数量 |

#### 响应约定

```json
{
  "code": 0,
  "data": {},
  "msg": "success"
}
```

错误状态要求：

- 400：请求结构错误。
- 401：未登录或会话过期。
- 409：提交的基础修订号已过期，防止覆盖其它已保存修改。
- 422：配置可以解析，但不满足发布规则；返回字段或配置路径级错误。
- 500：未预期服务端错误，响应中不包含密码、订阅 URL 或节点密钥等敏感信息。

### 6.5 服务端发布校验

前端校验只用于即时反馈，服务端校验是发布的唯一依据。发布至少检查：

#### YAML 模板

- 可以由 `yaml` 包完整解析。
- 根节点是 Mapping。
- 顶级键不重复。
- 不包含四个受管字段。

#### 策略组

- 启用组名称非空且唯一。
- 类型受支持，类型相关字段完整。
- 所有正则表达式可以编译。
- 所有引用指向存在且启用的策略组。
- 不存在循环引用。
- 启用组解析后没有成员时返回警告但不阻断发布，以兼容当前可能生成空组的行为；界面必须明确展示空组风险。

#### 规则提供者

- 启用提供者名称唯一。
- URL、行为模式、路径和更新间隔合法。
- 不允许同一路径被不同启用提供者重复占用。

#### 路由规则

- 目标策略组存在且启用。
- `RULE-SET` 指向存在且启用的提供者。
- 规则类型、匹配内容及 `no-resolve` 组合合法。
- 最终 `MATCH` 存在且位于最后。

所有错误需要返回稳定错误码、中文标题、具体路径和可读详情，例如：

```json
{
  "code": 1,
  "msg": "routing config is invalid",
  "errors": [
    {
      "code": "GROUP_REFERENCE_CYCLE",
      "path": "groups[group-ai].sources[1]",
      "message": "策略组存在循环引用：海外AI → 故障转移 → 海外AI"
    }
  ]
}
```

### 6.6 YAML 生成逻辑改造

`generateProxyConfigYaml.ts` 需要从“硬编码策略组”改造成“解释已发布配置”。推荐流程如下：

1. 按订阅类型读取并解析订阅节点，保留现有流量信息汇总逻辑。
2. 读取自建节点并在运行时追加 `【自建】` 后缀。
3. 继续应用对应 `SUBSCRIBE_PATTERN.EXCLUDE_PATTERN` 或 `ONETIME_PATTERN.EXCLUDE_PATTERN` 作为全局节点预过滤，首期不在 UI 中迁移该部署级过滤项。
4. 通用版使用完整兼容节点集；Stash 版先通过现有 `filterProxyForStash` 过滤。
5. 按策略组顺序解析成员来源：
   - 根据当前订阅类型忽略不适用的来源。
   - 节点筛选器先执行包含正则，再执行排除正则。
   - 策略组引用转换成被引用组的最新名称。
   - 内置策略直接写入。
   - 按来源和节点出现顺序去重，保留第一次出现的位置。
6. 生成启用的规则提供者，并保持配置顺序。
7. 生成启用规则，将 `providerId` 和 `targetGroupId` 转为名称，并保持规则顺序。
8. 使用 `YAML.parseDocument(baseYaml)` 创建文档，写入四个受管字段；禁止继续使用字符串直接拼接。
9. 分别序列化通用版和 Stash 版，并保留当前“最后更新时间”注释。

#### 必须保留的订阅接口行为

- `/subscribe/:magic` 对应“包年/包月”。
- `/onetime/:magic` 对应“流量包”。
- `magic` 不匹配时继续返回 403。
- User-Agent 包含 `stash` 时返回 Stash 版本，大小写不敏感。
- `subscription-userinfo` 响应头的计算方式不变。
- `Content-Disposition` 的下载文件名语义不变。
- `INSTANT_REFRESH_INTERVAL`、访问时间键和现有缓存命中/强制刷新判断保持不变。
- 没有订阅源或没有对应类型时，继续返回明确的注释文本而不是 500。
- 定时任务继续刷新两种订阅类型。

### 6.7 缓存失效规则

以下操作成功后必须删除两个现有缓存键：

- 保存订阅源。
- 保存自建节点。
- 发布路由配置。

缓存键保持：

- `${TABLENAME}:${KEY_VERSION}:cacheObj:包年/包月`
- `${TABLENAME}:${KEY_VERSION}:cacheObj:流量包`

以下操作不得清理正式缓存：

- 保存路由草稿。
- 配置校验。
- 完整输出预览。
- 在页面内切换页签、搜索或筛选。

### 6.8 旧配置迁移与回退

#### 迁移原则

- 未存在 `${TABLENAME}:routing:published` 时，订阅生成必须继续走旧逻辑，确保升级部署本身不改变输出。
- 首次打开路由配置页时，可以根据旧配置生成迁移草稿，但不得自动发布。
- 管理员必须查看差异、通过校验并主动发布后，新生成器才生效。

#### 迁移映射

1. 解析旧 `defaultYaml`。
2. 抽取 `rule-providers` 为规则提供者。
3. 抽取 `rules` 为结构化路由规则，并按名称建立稳定 ID 引用。
4. 删除受管字段后的剩余内容保存为 `baseYaml`。
5. 将 `generateProxyConfigYaml.ts` 中的旧策略组映射成策略组数据。
6. 将 `SUBSCRIBE_PATTERN` 与 `ONETIME_PATTERN` 中各组的 MATCH/EXCLUDE 正则映射为带适用输出范围的节点筛选器。
7. 如果两个订阅类型的正则相同，可以合并成 `appliesTo: "all"`；不同则保留两个来源。

#### 回退方案

- 新旧生成路径至少并存一个发布周期。
- 删除或停用新 `routing:published` 键后，可以立即回到旧生成路径。
- 回退不得删除草稿、旧 `${TABLENAME}:config` 或订阅源数据。
- 确认黄金样本、线上抽样和客户端加载均稳定后，再安排后续版本删除旧硬编码逻辑。

### 6.9 安全与日志要求

- 不记录登录密码、完整订阅 URL、自建节点密码、UUID 或密钥。
- `/api/save` 和 `/api/config` 当前输出整个请求参数的调试日志需要移除或脱敏。
- API 仅接受 JSON，限制合理请求体大小，避免超大 YAML 或 JSON 消耗 Worker 资源。
- 服务端不得信任前端生成的引用名称，必须根据稳定 ID 重新解析。
- 发布失败不能覆盖上一版已发布配置。

## 7. 如何验证符合原先实现效果

### 7.1 验证原则

验证分为两层：

1. **升级兼容验证**：只部署新代码但尚未发布新配置时，输出必须与旧版本等价。
2. **迁移等价验证**：将旧配置转换为新数据模型后，四类输出的 YAML 语义必须与迁移前等价。

不能只比较页面是否可用，也不能只检查 YAML 可以解析；必须检查节点、策略组成员、规则提供者、规则顺序和响应行为。

### 7.2 建立旧版黄金样本

开发新生成器之前，先为当前 `generateProxyConfigYaml.ts` 建立固定输入与输出快照。测试节点集至少包含：

- 普通 SS/VMess/Trojan 节点。
- 能被全局 `EXCLUDE_PATTERN` 命中的套餐、流量或官网节点。
- 能分别命中 AI、媒体、Telegram、Steam、Binance 等正则的节点。
- 同名节点，用于验证去重顺序。
- Stash 支持和不支持的节点协议或配置。
- 有自建节点与无自建节点两种情况。

对以下组合分别保存黄金样本：

| 订阅类型 | 客户端 | 自建节点 |
| --- | --- | --- |
| 包年/包月 | 通用 | 无、有 |
| 包年/包月 | Stash | 无、有 |
| 流量包 | 通用 | 无、有 |
| 流量包 | Stash | 无、有 |

### 7.3 YAML 语义对比方法

时间注释和无语义格式不应导致测试失败。对比时执行：

1. 移除“最后更新时间”注释。
2. 使用相同版本的 `yaml` 包解析旧、新输出。
3. 对以下部分分别断言：
   - `proxies`：节点对象内容与顺序一致。
   - `proxy-groups`：组名、类型、参数、成员及顺序一致。
   - `rule-providers`：名称与所有字段一致。
   - `rules`：规则文本与顺序完全一致。
   - 其它基础字段：解析后的 YAML 值一致。
4. 额外重新序列化并解析一次，确认不存在重复顶级字段或不稳定结构。

如果新模型有经过确认的预期差异，必须在测试用例中逐条记录原因，禁止使用整段快照更新掩盖差异。

### 7.4 单元测试

至少覆盖以下模块：

#### 节点筛选与策略组解析

- 包含正则、排除正则和空正则。
- `all`、`subscription`、`self` 三种范围。
- `all`、`monthly`、`trafficPackage` 三种适用输出。
- 多来源合并后的稳定去重。
- 策略组引用改名不失效。
- 不存在引用、自引用和多组循环引用。
- 通用版与 Stash 版使用不同节点池。

#### 规则与提供者

- `RULE-SET` 通过 `providerId` 生成最新名称。
- 目标策略组通过 `groupId` 生成最新名称。
- 禁用项不输出。
- `MATCH` 始终位于最后。
- 规则顺序在保存、读取和生成后不变化。

#### YAML 模板

- 合法 Mapping 可以合并。
- 无效语法、重复顶级键和四个受管字段被拒绝。
- DNS、TUN、profile 及未知顶级字段原样保留语义。
- 注释在未执行格式化时尽可能通过 `YAML.Document` 保留。

#### 迁移

- 当前 `defaultYmal.ts` 可以完整拆分再组合。
- 所有旧规则目标策略组均能建立引用。
- 所有旧 `RULE-SET` 均能找到提供者。
- 月付与流量包不同环境正则不会被错误合并。

## 8. 推荐开发顺序

以下条件全部满足才视为本需求完成：

- 新 UI 覆盖登录与四个业务页面，并与原型的视觉层级和交互一致。
- 所有页面均已清除无实际功能元素。
- 策略组、规则提供者和路由规则可以不改代码完成新增、编辑、排序、校验和发布。
- DNS 及其它非受管字段统一在 YAML 模板中维护。
- 自建节点和路由配置使用独立保存通道，不会相互覆盖。
- 发布失败不会影响上一版有效订阅。
- 两类订阅源、两类客户端共四种输出均通过语义兼容测试。
- 订阅端点、响应头、认证、缓存和定时任务通过回归测试。
- 不记录密码、订阅密钥或节点密钥等敏感信息。
- `pnpm run typecheck`、`pnpm run test` 和兼容测试全部通过。
- 开发说明中记录 KV 新键、迁移步骤、回退方法和已知限制。

## 10. 常见问题

### 为什么 DNS 不单独做表单？

DNS 与 TUN、sniffer、profile 等都属于 Clash 客户端基础配置，而且不同客户端和版本字段变化较快。统一保留原始 YAML 能避免做出不完整表单，也符合本项目“生成订阅文件而非控制 Clash 进程”的定位。

### 为什么自建节点仍然使用 JSON？

不同节点协议字段差异较大，固定表单容易丢失插件或新协议字段。JSON 编辑器配合结构校验和解析摘要，在灵活性与易用性之间更合适。

### 为什么 `proxies` 不能手工编辑？

它来自订阅源和自建节点的实时合并结果。允许手工编辑会在刷新订阅时被覆盖，也会造成节点来源不清晰。

### 为什么需要草稿与发布两步？

路由错误会直接影响所有客户端。草稿允许先校验和预览四类输出；只有发布才清缓存并影响订阅地址，同时仍不引入复杂审批流。

### 新版本部署后会立即改变订阅吗？

不会。没有新 `routing:published` 数据时继续使用旧生成路径。只有管理员主动发布迁移后的配置，新生成器才开始生效。

### 是否需要保留旧环境变量中的分组正则？

迁移期需要。组级 MATCH/EXCLUDE 正则会转换成可视化节点筛选器；两个订阅类型不同时使用“适用输出”分别保存。全局 `EXCLUDE_PATTERN` 首期继续作为部署级节点预过滤，后续如需在 UI 中管理可另立需求。
