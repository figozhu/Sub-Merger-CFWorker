# SubMerger 完整控制台原型

## 1. 覆盖范围

原型依据当前 Worker 的真实页面和配置能力设计，只保留五个界面：

| 界面 | 对应现有能力 |
| --- | --- |
| 登录 | `POST /login` 密码验证 |
| 订阅源 | 维护名称、类型、订阅地址并保存到 `/api/save` |
| 自建节点 | 维护任意 Clash 节点 JSON，并通过 `/api/config` 保存 |
| 路由配置 | 可视化维护策略组、路由规则、规则提供者和非路由 YAML 模板 |
| 订阅输出 | 展示 `/subscribe/:magic` 与 `/onetime/:magic` 并复制 |

没有加入总览、系统设置、环境状态、账户菜单等当前项目没有操作闭环的页面或入口。

## 2. 全局信息架构

登录后侧栏只有四个业务入口：

1. **订阅源**
2. **自建节点**
3. **路由配置**
4. **订阅输出**

页面标题栏只显示保存状态以及当前页面可执行的主要操作。没有面包屑、功能宣传、架构版本、运行区域或装饰性指标。

## 3. 页面设计

### 登录

- 单一密码字段、显示/隐藏密码和登录按钮。
- 错误直接显示在字段下方。
- 原型演示密码为 `admin`。

### 订阅源

- 表格直接编辑名称、订阅类型和 URL。
- 支持添加、删除确认、逐字段校验和保存状态。
- 不增加与当前数据模型无关的流量统计或机场状态。

### 自建节点

- 继续使用 JSON，以保留项目对任意 Clash 节点协议的兼容性。
- 左侧只显示从 JSON 实时解析出的节点；右侧提供编辑、格式化、结构校验和保存。
- 不把不同协议强制拆成不完整的表单。

### 路由配置

- **策略组**：编辑名称、类型、成员来源、健康检查和节点匹配结果。
- **路由规则**：分类筛选、搜索、启停、拖动排序、修改目标策略和删除。
- **规则提供者**：编辑名称、行为模式、下载地址、更新间隔和生成路径。
- **YAML 模板**：维护所有非受管顶层字段，左侧大纲仅负责定位。

配置所有权如下：

- `proxies` 由订阅合并过程生成。
- `proxy-groups`、`rule-providers`、`rules` 由可视化配置生成。
- DNS、端口、TUN、sniffer、profile 等其它字段全部保留在同一个 YAML 模板中。
- 模板写入受管字段时，发布校验必须阻止覆盖。

### 订阅输出

- 只展示两类真实输出地址、对应订阅源数量和复制操作。
- 不增加没有后端能力支撑的运行日志、在线测试或刷新按钮。

## 4. 非功能元素清理规则

本轮逐页应用以下判断：

- 元素必须展示可编辑数据、可验证状态或可执行操作之一。
- 架构说明、操作流程示意和教学卡片不占据主界面空间。
- 空白区域不使用虚构指标或说明内容填充。
- 暂无实现的按钮直接移除，不保留“以后可用”的入口。
- 必要的格式、数量、错误和引用信息可以保留，因为它们直接影响当前操作。

## 5. 原型交互

- 登录成功与失败状态。
- 订阅源新增、校验、保存与删除确认。
- 自建节点 JSON 实时解析、错误阻断、格式化与保存。
- 四个路由配置页签以及新增、编辑、删除、排序、校验、导入、预览和发布流程。
- YAML 大纲定位、模板冲突检查及 Clash / Stash 输出切换。
- 两类订阅链接复制反馈。

原型数据只存在浏览器内存中，不会请求 Worker API 或修改 Cloudflare KV。
